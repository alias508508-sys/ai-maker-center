# AI maker 数据维护与研究使用

目标是让网站持续运行，并把可追溯的案例积累为研究材料。运行库、完整备份和研究副本承担不同责任，不互相替代。

## 当前规模（2026-10-07 实测）

PostgreSQL 约 38 MB，保存 496 条材料、270 条分析记录、222 条发布状态记录；当前首页公开案例为 191 条。分析和发布记录不是独立案例数量，不能相加。当天新入库材料 104 条、前一天 216 条，只统计持久化数据库材料，不能等同于搜索接口返回的全部帖子或网页数。

静态站目录约 13 MB，运行数据目录约 98 MB，服务器完整加密备份累计约 295 MB。当前规模无需迁移数据库或为省空间删除原始材料；先持续观察实际增长。

## 三份数据各自的作用

| 数据 | 内容 | 用途 |
| --- | --- | --- |
| 运行数据库 | 原始材料、来源、链接、时间、分析版本、审核、发布状态和处理记录 | 去重、审核、网站运行、问题追溯 |
| 完整加密备份 | 数据库、项目与运行文件、图片、配置及运维环境 | 故障恢复，配合独立保管的恢复密钥 |
| 研究案例库 | 案例事实、来源链接、摘要、研究者编码及笔记 | 筛选比较、质性分析、论文案例与方法研究 |

研究案例库使用运行库的副本或公开资料导出，不直接修改原始材料和网站评分。只复制 PostgreSQL 数据目录里的零散文件不是完整可恢复备份；继续使用现有数据库导出和加密完整包。

## 维护安排

### 每日检查

- 采集、审核、发布任务最近执行是否成功；审核凭证或余额异常时保留待处理记录，不放行。
- 新材料、相关内容、审核拦截、实际新增公开内容及付费调用分别统计，避免把“搜索返回数”当作“发布文章数”。
- 新链接去重，已有内容复用分析与审核缓存；正文或策略版本改变时才按既有规则重新处理。
- 检查 04:10 完整加密备份、外层 SHA256 和 04:30 网盘读回状态；电脑不在线只影响网盘同步，服务器备份仍独立执行。

### 每周检查

- 观察数据库、图片、运行日志和备份的增长趋势，检查磁盘余量及慢查询；现阶段先记录，避免没有证据就添加索引或重构。
- 区分失败信源、没有新内容和被审核拦截；保留原有信源，失败不能无记录地删除。
- 检查同一链接是否重复分析、不同链接是否其实在介绍同一个项目。链接去重解决采集重复；研究时还需要按“项目/事件”归组，两个报道不一定是两个创新案例。

### 每月整理

- 输出当月研究资料快照与统计，保留数据范围、导出时间、字段字典和版本。
- 在隔离环境验证备份能解密、校验并恢复到临时数据库，不能只看包大小。网站数据库继续运行，不在生产库做恢复试验。
- 评估备份保留策略与成本。可以考虑近期每日备份加长期月度备份，但需要明确保留策略后再清理；当前不自动删除历史完整包或原始材料。

以上“每周/月”是建议的维护安排，不代表已新增相应自动任务。现有固定定时器与实际核验方法见 [固定生产流程](maker-operations.md)。

## 研究案例库的组织

### 基础事实与证据

每个案例保留稳定 ID、项目名称、作者/机构、原文链接、来源类型、原文发布日期、采集时间、原始文本及可用图片的引用、中文摘要、原文核对状态。缺失日期标“未提供”，不能用导出时间伪装成发布日期或采集时间。

网站 AI 生成的分类、摘要、评分与分析版本单独保存，供初筛和过程研究；论文中的事实仍回到原文核对。内容审核通过表示满足当前发布策略，不证明消息真实、项目有效或研究质量高。

### 研究者编码与分析

研究“AI 创新的方法”可以先用以下维度建立编码表，再根据研究问题、理论与样本试编码修订；这些维度是工作建议，不是已经验证的学术量表。

| 维度 | 可记录的内容 |
| --- | --- |
| 问题与应用场景 | 解决什么需求，面向谁，在什么环境中使用 |
| AI 技术方法 | 大语言模型、视觉识别、生成式设计、强化学习、端侧推理等，以原文证据为准 |
| 创新方式 | 新功能、交互方式变化、流程重组、产品服务融合或教学实践变化 |
| 人机协作 | 人如何提出目标、选择结果、验证输出及承担控制 |
| 数据与实现 | 使用什么数据、硬件、接口或开源组件，是否可复现 |
| 证据强度 | 概念宣传、可运行演示、开源实现、实验结果、实际部署，分别记录 |
| 限制与风险 | 原文已知限制、研究者发现的问题及待验证项 |
| 方法比较 | 与哪些案例相似或不同，形成哪些设计策略或创新路径 |

原文事实、AI 判断和研究者解释分列。重要案例先保存证据摘录与定位，再写案例卡片；不要把网站分数直接当作“创新程度”的测量值。

## 适合交付的文档形式

- Excel/CSV 案例总表：方便筛选、批量编码、透视统计和导入研究工具。
- Word/Markdown 案例卡片：每个案例包含背景、AI 方法、创新机制、证据、限制和原文链接，适合继续扩写论文。
- 月度研究简报：按领域和方法汇总趋势，给出有证据的案例比较；同时记录筛选规则与局限。
- 原始结构化快照（JSON）：保留机器可读数据和导出范围，便于复核及后续版本比对。

当前已导出 191 条首页公开案例的 CSV 与 JSON 初始快照，保留摘要、来源链接、网站分类及评分，并留空研究者编码列；缺失的原文/采集日期不填造。此快照不是完整数据库、全文语料或备份，不能覆盖历史已下架案例或全部采集候选。

## 研究结论的边界

这是由既有信源、AI 搜索词、相关性筛选、语言与访问限制、审核策略和发布门槛共同形成的样本，不是“全球 AI 创新”的完整总体。后续研究应记录这些采样条件；帖子数量、媒体热度和创新方法的实际有效性不能混为一谈。只公开摘要和来源入口，全文、截图及其他材料的再发表需要分别核对来源许可与引用范围。

默认研究导出只用公开案例，不混入密钥、会话、管理员信息、私人投稿和内部回执。若需要分析未发布材料，另外建立脱敏私有研究集，保留采集/审核/发布状态并控制访问，不将其回灌公开页面。
