# 管理员投稿与发布

入口 `/admin/submissions`，沿用管理员登录和 CSRF 校验。支持公开文章链接、自己写的标题与正文、自动或指定分类、最多六张配图。首张裁剪为封面；原创正文和全部配图另存可访问的全文页面，原文不会被模型改写。链接只公开摘要与原文入口。

投稿先保存在 PostgreSQL 的 `maker_submissions`，重复请求通过 Idempotency-Key 去重并写入审计。页面显示排队、处理中、已发布或失败，并定时刷新状态。失败仍保留原稿；不自动重试可能已经扣费的任务。

`deploy/maker/` 是当前服务器的 systemd 发布服务模板。每分钟尝试处理一个投稿，与六小时自动采集共用 `/run/maker-collect.lock`，避免同时修改静态数据。正常需要一分钟排队、模型和抓取耗时，以及原框架三分钟公开门槛；定时采集运行时会顺延。所有模型调用使用现有回执和预算，不绕过熔断。公布内容先经过统一 publication 读取层，再生成封面、日期归档和首页。

服务需要数据库迁移 0042 和新应用镜像。只绑定 localhost 的后台仍通过 SSH 隧道访问；公网静态站点不暴露投稿 API。站主原稿、请求状态、分类存在数据库，公开页面与配图位于 `pages-preview`，由现有数据库及站点备份一同保护。仓库只提交代码，不提交私人投稿队列。
# 自动封面

投稿与定时采集都会运行 `scripts/maker-covers.ts`：优先取社交分享封面，其次提取正文图片（包含懒加载地址和 srcset），下载并筛选尺寸，生成本地 960×540 WebP。无法直接取得合适原图时，使用 Chromium 渲染页面并截取可见的大图片元素。浏览器资源通过现有 SSRF 安全请求层获取，禁止私网访问和 WebSocket；不绕过登录或访问限制。

每轮最多检查 25 条、尝试 3 次浏览器渲染，超出浏览器额度的条目留待后续采集。已有封面保持不变；旧的“无封面”记录按新版本重新检查。最终无法获取图片时继续显示文字，不使用替代封面。服务器 Docker 镜像已包含 Chromium，GitHub runner 会在有 Chromium/Chrome 时启用截图备用流程。
