# AI maker 固定生产流程

此文件记录生产流程约束。新增信源和修改部署时必须保留以下步骤；真实运行状态以服务器定时器、服务退出结果、审核记录及备份校验为准。

## 发布顺序

既有网页/RSS信源与 X 自动搜索并行 → 链接及内容身份去重 → 原始文字审核 → AI 分类、中文整理及相关性判断 → 原始材料和生成文字共同审核 → 统一公开读取门槛 → 获取缩略图 → 转换后的实际图片审核与静态内容复核 → 历史归档 → 首页生成。

服务器采集脚本顺序固定为 `maker-auto.ts` → `maker-covers.ts` → `maker-moderate.ts` → `maker-archive.ts` → `maker-pages.ts`；脚本失败停止后续步骤。投稿使用相同审核、封面、归档及页面生成链。数据发布层、首页和榜单分别核对数据库审核结果与私有内容哈希缓存，未知或未通过的内容不得公开。封面改变需重新审核实际字节。

生产 `CONTENT_SAFETY_ENABLED` 必须保持启用。审核超时、无权限、余额或预算不足不能改为绕过审核；未通过内容保留在私有队列或隔离目录，等待既有重试流程处理。不能为验证而重复调用付费审核，优先读取已有回执和缓存。

已有信息源保持采集；X 每天由 AI 为四个方向生成搜索计划，再用数据接口查询真实帖子，不把生成的账号或链接当作真实信源。YouTube 自动采集暂不启用，已有发布样例保留。

首页新增公开文章置前，已有卡片刷新不按原文日期打乱。每日榜单按评分推荐，必须有已审核缩略图；新增不足时按此前榜单顺序补位，最多 8 篇。榜单引用的内容也必须仍有有效审核结果。

## 固定任务（北京时间）

| 任务 | 频率 | 责任 |
| --- | --- | --- |
| `maker-collect.timer` | 00:17、06:17、12:17、18:17 | 自动采集、AI 分析、审核、归档、首页生成 |
| `maker-submissions.timer` | 约每分钟检查 | 处理后台投稿，保留原稿及状态 |
| `maker-moderate.timer` | 每 5 分钟 | 复查待审核内容并生成过滤后的首页 |
| `maker-rankings.timer` | 每日 08:30 | 评分推荐及旧榜补位，生成首页 |
| `maker-backup.timer` | 每日 04:10 | 完整加密备份及 SHA256 校验 |
| Codex 网盘同步 | 每日 04:30 | 上传最新未同步加密包与校验文件，读回确认 |

服务器任务共享 `/run/maker-collect.lock`，避免采集、投稿、审核、榜单和备份同时修改文件；锁冲突按各任务配置等待或顺延。日历定时器设有 `Persistent=true`，可在服务器恢复运行后补执行错过的日历任务；仍需检查退出结果，不能把“定时器启用”当作任务成功。

## 完整备份

实现：`deploy/maker/maker-backup-full`，生产入口 `/usr/local/sbin/maker-backup`。完整包包含数据库导出、项目及私密运行配置、Git 历史、应用数据卷、证书和 systemd/运维配置；数据库中的审核记录和付费回执一并保存。GPG AES256 加密后保存于 `/root/maker-backups/full-*.tar.gz.gpg`，附同名 `.sha256`。备份脚本检查数据库导出、加密包可解密列出及外层校验文件，失败不得报告成功。

只上传加密包与校验文件到 Google Drive；恢复密钥单独保管。上传后读取元数据核对文件名、大小和目录，并写入 `.data/drive-backup-state.json` 防止重复。服务器备份不依赖 Codex 电脑，网盘同步依赖电脑及连接器可用。故障时保留服务器及本地旧副本，不自动删除历史完整备份。

后续运维检查应包含：五个业务定时器的启用/下次时间、最近服务退出结果、审核开关及凭证就绪状态（只输出布尔值）、未通过内容是否隔离、公开内容是否全部有效审核、最新完整备份的时间及 SHA256，以及异地副本读回结果。整机恢复不能用“文件存在”代替真实恢复验证。

## 搜索与分享入口

`maker-pages.ts` 每次生成首页时，使用同一批审核通过的内容生成文字版摘要、分享元数据、`robots.txt` 和 `sitemap.xml`。网站地图只列存在的正式站内页面及当前公开投稿，不列外站原文、后台、私有数据和未审核投稿。静态首页不能直接使用框架的通用 sitemap：其中列出的框架页面在当前部署中可能不存在。

`deploy/maker/mobile-nginx.conf` 为静态页面开启 gzip，并将 `/favicon.ico` 和 `/og/site.png` 转发到既有应用服务。更新后检查网站地图中所有链接返回 200、首页压缩传输、手机宽度分页与筛选、RSS 和后台登录，并复核上述审核及备份任务。微信移动网络访问仍需真实手机验证，不能以浏览器模拟或服务器日志代替。

## 研究导出边界

研究资料使用数据库的公开案例子集，保留来源、原文链接、采集时间及分析版本。原文事实、AI 整理/评分和研究者编码分开保存。审核拦截或私人投稿不能默认公开；账号密钥、管理员密码、会话、通知地址、系统配置及内部回执不能随案例资料导出。研究资料副本不能替代完整加密备份。
